# Geo-Global

# План проекта (primary)

---

### 1. Ключевая архитектурная идея: Модульность через паттерн "Мост" (Bridge)

Для одновременного выполнения двух требований — "каждая новая фича в отдельном namespace" и "базовый макет общий для всех" — идеально подходит паттерн **"Мост" (Bridge)**, который является мощной реализацией принципа SOLID (Open/Closed).

Эта архитектура позволит добавлять новые тематические контексты (биология, техника), никак не изменяя код отображения глобуса и навигации. Это делает систему невероятно расширяемой.

```mermaid
flowchart TD
    A[Пользовательский Интерфейс<br>UI / Панель вкладок] --> B[Контроллер приложения<br>AppController]

    B --> C[Модуль ядра<br>Core 3D Scene]
    B --> D[Модуль данных<br>DataManager]

    subgraph C [Модуль отображения]
        C1[Базовый глобус<br>BaseGlobe]
        C2[Менеджер слоёв<br>LayerManager]
    end

    B --> C2

    subgraph D [Модуль данных]
        D1[Абстрактный загрузчик<br>AbstractDataLoader]
    end

    subgraph E [Тематические Контексты (Contexts)]
        E1[Контекст Истории<br>HistoryContext]
        E2[Контекст Биологии<br>BioContext]
        E3[Контекст Географии<br>GeoContext]
    end

    B --> E1 & E2 & E3
    E1 & E2 & E3 --> D1
    E1 & E2 & E3 --> C2

    D1 --> F[Внешние API / Базы данных]
```

### 2. Технический стек и инструменты

Для создания такого сложного SPA (Single Page Application) потребуется современный и производительный стек.

*   **Бэкенд (Сервер и API):** 
    *   **Node.js + Express.js:** Основа сервера для обработки запросов и проксирования внешних API.
    *   **MongoDB или PostgreSQL:** Для хранения пользовательских данных, избранных маркеров, заметок и кэша геоданных.
    *   **Prisma (ORM):** Для удобной и типобезопасной работы с базой данных .

*   **Фронтенд (Визуализация и UI):**
    *   **Vite:** Как сборщик проекта. Он невероятно быстр и идеально подходит для сложных Three.js-приложений .
    *   **Three.js:** Основная библиотека для 3D-рендеринга .
    *   **TypeScript:** Строгая типизация критически важна для поддержки модульной архитектуры и долгосрочной разработки . Это не просто "хорошо", а необходимость для вашего проекта.
    *   **CSS Modules или TailwindCSS:** Для стилизации интерфейса, не вмешиваясь в глобальные стили.

*   **Работа с геоданными и картами:**
    *   **CesiumJS или Harp.gl:** Альтернатива для рендеринга глобуса, если потребуется более глубокая работа с геопространственными данными. Они могут работать поверх Three.js .
    *   **GeoJSON, TopoJSON:** Основные форматы для хранения и отображения границ государств, рек и т.д. .

### 3. Модульная структура проекта (MVC & SOLID)

Организация папок должна чётко отражать архитектуру:

```
project-root/
├── server/                       # Бэкенд-часть (Node.js + Express)
│   ├── src/
│   │   ├── controllers/          # MVC: Контроллеры (обработка запросов)
│   │   ├── models/               # MVC: Модели данных (Prisma модели)
│   │   ├── services/             # Бизнес-логика (работа с внешними API, кэширование)
│   │   └── routes/               # Маршруты API
│   └── prisma/
│       └── schema.prisma         # Схема базы данных
│
└── client/                       # Фронтенд-часть (Vite + Three.js)
    ├── src/
    │   ├── core/                 # Ядро визуализации
    │   │   ├── BaseGlobe.ts      # Базовый класс Земли, общий для всех
    │   │   └── SceneManager.ts   # Управление сценой, камерой, рендером
    │   ├── layers/               # Слои отображения
    │   │   └── LayerManager.ts   # Абстрактный класс для добавления/удаления слоев
    │   ├── contexts/             # Тематические контексты (фичи)
    │   │   ├── history/          # Модуль "История"
    │   │   │   ├── HistoryContext.ts
    │   │   │   ├── layers/       # Специфичные слои для истории (границы, маркеры)
    │   │   │   └── dataLoader/   # Загрузчики данных для истории
    │   │   ├── geography/        # Модуль "География"
    │   │   └── biology/          # Модуль "Биология"
    │   ├── ui/                   # Элементы интерфейса
    │   │   ├── App.tsx
    │   │   ├── components/       # UI компоненты (панель вкладок, окно информации)
    │   │   └── styles/
    │   ├── utils/                # Вспомогательные функции (математика, работа с GeoJSON)
    │   └── types/                # Глобальные TypeScript-интерфейсы
    └── index.html
```

### 4. План реализации (Этапы)

#### Этап 1: Фундамент (Неделя 1-2)
1.  Настройка проекта: инициализация `client/` и `server/` с Vite и TypeScript.
2.  Создание базового класса `BaseGlobe` и `SceneManager` в Three.js. Должен отображаться земной шар с текстурами .
3.  Настройка `OrbitControls` для вращения и приближения .
4.  Написание абстрактного класса `LayerManager` и `AbstractDataLoader` (интерфейсы будущей модульности).

#### Этап 2: Модульность и Переключение Контекстов (Неделя 3-4)
1.  Создание структуры для контекстов. Реализация `AppController`, который управляет активным контекстом.
2.  Создание первого тестового контекста (например, "География"). При его активации с помощью `LayerManager` на глобус добавляются слой с границами и слой с маркерами столиц.
3.  Отработка анимации переключения контекстов (затухание/наплыв слоёв).

#### Этап 3: Работа с Данными и Внешними API (Неделя 5-6)
1.  Реализация серверной части для проксирования внешних API.
2.  Подключение к **бесплатному и открытому API** для данных:
    *   **Для границ государств:** API **Restcountries** или файлы **GeoJSON**.
    *   **Для биологических данных:** API **GBIF (Global Biodiversity Information Facility)** для получения данных о находках видов. Это один из крупнейших и наиболее полных бесплатных научных ресурсов .
    *   **Для исторических данных:** Сбор данных из открытых исторических атласов (API не всегда стабильны, но есть инициативы по оцифровке).
3.  Написание конкретного загрузчика (например, `RestCountriesLoader`), наследующего `AbstractDataLoader`, для получения и парсинга границ в формат для `LayerManager`.
4.  Настройка кэширования на сервере (Redis или просто в MongoDB), чтобы не грузить внешние API при каждом запросе .

#### Этап 4: Интерактивность и UI (Неделя 7-8)
1.  Реализация Raycaster (Three.js) для обработки наведения и кликов по маркерам и территориям.
2.  Создание информационного попапа или боковой панели, которая показывает данные о выбранном объекте.
3.  Связка UI с `AppController`: клик на вкладку "Биология" → активация `BiologyContext` → загрузка данных о распространении видов → отображение маркеров на глобусе.

### 5. Особенности и вызовы

*   **Производительность:** 3D-глобус с огромным количеством маркеров (например, все виды из GBIF) может тормозить. Используйте LOD (Level of Detail) — при отдалении группируйте маркеры в кластеры или точки, при приближении — детализируйте. .
*   **Качество данных:** Данные из открытых источников могут быть неполными или иметь ошибки. Архитектура должна предусматривать "слой валидации" данных на сервере перед отправкой на клиент.
*   **Актуальность в реальном времени:** Для температуры и событий вы можете использовать **Planetary Computer от Microsoft**. Он предоставляет API на основе STAC (SpatioTemporal Asset Catalogs) для доступа к актуальным спутниковым данным .

### 6. Рекомендации по реализации из поисковых результатов

*   **Модульность:** Важно отделить UI (React/HTML) от 3D-сцены (Three.js). Используйте паттерн MVC, как это реализовано в проектах-примерах .
*   **Типизация:** TypeScript — ваш главный друг. Используйте его для описания моделей данных, в том числе для GeoJSON Feature-объектов .
*   **Подход:** Начните с создания скелета проекта (макета), определив основные интерфейсы (`ILayer`, `IContext`, `IDataProvider`). Это полностью соответствует вашему желанию сначала реализовать всё через абстракции.
